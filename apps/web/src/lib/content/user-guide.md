## 기본 구조

MonkeyBot은 Discord 길드별로 내전 운영 데이터를 분리합니다. 상단 길드 선택 메뉴에서 서버를 바꾸면 내전,
경매, 전적, 랭킹, 관리 화면도 선택한 길드 기준으로 전환됩니다.

- **내전**: 일반 내전 모집, 엔트리 편성, 픽밴, 결과 입력
- **경매**: 10인 또는 20인 경매 모집, 입찰, 브래킷, 라인업, 결과 입력
- **전적**: 길드 내부 일반/경매 내전 기록과 외부 Riot 전적 검색
- **랭킹**: 현재 길드와 시즌의 포지션별 MMR
- **관리**: 길드 운영자 전용 멤버, 길드 설정, 시즌, 감사 로그

길드를 변경해도 다른 길드의 모집, 전적, MMR에는 영향을 주지 않습니다.

## 시작하기

1. 길드 운영자는 Bot을 설치한 뒤 Discord에서 `/초기설정`을 실행합니다.
2. 참가자는 Discord에서 `/등록 GameName#TagLine`으로 현재 길드 소속과 Riot 계정을 함께 등록할 수 있습니다.
3. 웹에서는 Discord 계정으로 로그인한 뒤 상단 길드 선택 메뉴에서 작업할 서버를 고릅니다.
4. 처음 열 길드는 **내 정보 → 대표 길드**에서 지정합니다.

`/등록`은 별도 회원가입이 아닙니다. Discord user ID를 기준으로 현재 길드 소속을 만들고 입력한 Riot ID를
연결합니다. 같은 사용자가 여러 길드에서 등록하면 Riot 계정은 재사용하지만 내전 전적과 MMR은 길드별로
분리됩니다.

모집 채널은 필수입니다. 엔트리, 결과 알림, 운영 로그 채널은 길드 설정에서 필요할 때만 지정합니다.

## 일반 내전

일반 내전은 하나의 시리즈를 중심으로 운영합니다. 모집 생성 시 BO1/BO3/BO5와 하드 피어리스 여부를 정하면,
해당 규칙은 엔트리와 시리즈에 그대로 유지됩니다.

### 운영 순서

1. Discord `/내전모집` 또는 **내전 운영**의 `내전 모집`에서 모집을 만듭니다.
2. 참가와 취소, 선호 라인 입력은 Discord 모집 메시지에서 처리합니다. 운영자는 Web에서 길드 멤버를 수동으로
   추가하거나 제거할 수 있습니다.
3. 정원이 찬 모집을 마감하고 엔트리 편성에서 두 팀의 다섯 포지션을 배치합니다.
4. 시리즈를 만든 뒤 픽밴 작업대에서 실제 진영을 선택하고 각 세트의 픽, 밴, 승리 팀을 입력합니다.
5. 확정된 결과는 길드 MMR과 내전 전적에 반영됩니다.

하드 피어리스 시리즈에서는 이전에 확정된 세트에서 **픽한** 챔피언을 다음 세트에서 다시 픽할 수 없습니다.
일괄 입력은 픽밴 단계와 진영 선택이 완료된 뒤에만 사용할 수 있습니다.

모집 취소/재개, 엔트리 초기화, 시리즈 복귀 또는 삭제, 마지막 세트 되돌리기, BO3/BO5 조기 종료는 화면에
표시된 권한과 상태에서만 사용할 수 있습니다.

## 경매 내전

경매 내전은 참가 인원에 따라 대진 구조가 다릅니다.

| 인원 | 팀 구성   | 대진                 |
| ---- | --------- | -------------------- |
| 10인 | 2팀 x 5명 | 결승 1경기           |
| 20인 | 4팀 x 5명 | 준결승 2경기 후 결승 |

### 생성과 규칙

Discord `/경매모집` 또는 **경매**의 모집 생성에서 10인/20인, 결승 BO1/BO3/BO5, 하드 피어리스를 정합니다.
20인 경매는 준결승 BO도 별도로 정합니다. 생성한 규칙은 토너먼트와 각 경기로 복사되며 진행 중에는 바꿀 수
없습니다.

### 운영 순서

1. Discord 모집 카드 또는 운영자의 Web 수동 추가로 참가자 roster를 채웁니다.
2. 모집을 마감하고 팀장과 팀별 시작 포인트를 설정한 뒤 토너먼트를 만듭니다.
3. 경매 드래프트에서 후보를 뽑아 낙찰, 유찰 또는 수동 배치합니다. 모든 팀이 다섯 명으로 채워지면 브래킷
   설정 단계로 전환됩니다.
4. 브래킷에서 대진을 확정합니다. 10인은 결승 match로, 20인은 준결승 두 경기의 20명 라인업을 함께 정하는
   화면으로 이동합니다.
5. 라인업을 확정한 뒤 각 match에서 픽밴과 세트 결과를 입력합니다. 20인은 두 준결승 라인업이 모두 확정되기
   전에는 어느 준결승도 결과 입력으로 진행할 수 없습니다.
6. 모든 필요한 match가 끝나면 토너먼트 결과와 MMR 반영 기록을 확인합니다.

현재 후보의 **상세보기**에서는 모집 시점 MMR, Riot 티어, 길드 내전 요약, 선호 챔피언과 최근 내전 기록을
확인할 수 있습니다. 이 정보는 참고용이며 입찰 기준 MMR을 바꾸지 않습니다.

최근 입찰 되돌리기, 브래킷 확정 해제, 입찰 단계 복귀, lineup 확정 해제, 마지막 세트 되돌리기는 해당 화면의
권한과 상태가 허용할 때만 표시됩니다. 운영자는 Web 작업 화면의 **마무리**로 입찰·대진 설정·경기 진행 중인
10인/20인 내전을 종료할 수 있습니다. 확정된 경기 기록과 MMR은 유지되며, 10인전은 현재 경기, 20인전은
결승에서 앞선 팀이 우승합니다. 동점 또는 결승 미진행이면 우승팀 없이 완료합니다. 미확정 세트는 기록되지
않으며 마무리 후에는 결과를 수정할 수 없습니다.

**취소**는 확정된 경기와 MMR 반영을 되돌리는 별도 작업입니다. 경매 모집의 안전 취소와 토너먼트 취소는
해당 Web 작업 화면 또는 Discord 운영 명령에서 처리하며, 실제 가능 여부는 현재 상태와 권한에 따라 달라집니다.

## 전적 검색

상단 검색을 열면 **Riot**과 **내전** 검색을 선택할 수 있습니다.

- **Riot**: `GameName#TagLine`으로 외부 Riot 전적을 조회합니다.
- **내전**: 현재 선택 길드의 Discord 멤버, 공개된 연결 Riot ID, 내전 관련 검색어를 사용해 내부 기록을
  찾습니다. 입력 중 자동완성 결과를 선택할 수 있습니다.

길드 전적에서는 포지션별 MMR, 선호 챔피언, 일반/경매 내전 기록, 세트별 픽/밴과 라인업을 확인합니다.
10인 경매는 단일 series 기록으로, 20인 경매는 준결승/결승을 포함한 tournament 기록으로 표시합니다.

Riot 연결 공개를 허용한 사용자의 Riot ID만 길드 전적에 보입니다. 이 개인정보 설정은 외부 Riot 전적 검색을
막지 않으며, 같은 길드의 내전 기록과 MMR도 숨기지 않습니다.

## 랭킹

랭킹은 현재 길드의 **활성 시즌** 포지션별 MMR을 기준으로 집계합니다. 포지션 탭, 검색, 표시 인원 수를
바꿔서 순위를 확인할 수 있으며 다른 길드의 MMR과 합산하지 않습니다.

## 내 정보

아바타 메뉴의 **내 정보**에서 개인 설정을 관리합니다.

### 선호 챔피언

포지션별 선호 챔피언을 검색해 추가하고 순서를 바꾼 뒤 저장합니다. 이 목록은 실제 사용 전적과 별개이며
편성, 경매 후보 상세, 길드 전적에서 참고 정보로 사용됩니다.

### Riot 계정

`GameName#TagLine`으로 Riot 계정을 연결하고, 메인 계정 지정, 갱신, 연결 해제를 처리합니다. PUUID를 직접
입력할 필요는 없습니다.

### 대표 길드와 개인정보

대표 길드는 웹 루트에서 자동으로 열리는 길드입니다. 개인정보에서는 외부 프로필, Discord와 연결된 Riot ID,
외부 전적 검색 허용 설정을 관리합니다. 현재 길드 내전 전적은 같은 길드의 활성 멤버만 조회할 수 있습니다.

## 길드 관리

관리 메뉴는 해당 길드의 운영자에게만 표시됩니다.

- **멤버**: 길드 멤버 상태와 포지션별 MMR을 확인하고 권한이 있을 때 MMR 조정 또는 활성 상태 변경
- **길드 설정**: 운영자 역할, 모집/엔트리/결과/운영 로그 채널, 외부 공개 설정
- **시즌**: 현재/종료 시즌의 집계를 확인하고 `새 시즌 시작`으로 새 운영 기간 생성
- **감사 로그**: 관리 작업의 실행자, 대상, 시각과 저장된 상세 내용 확인

현재 운영 범위에는 별도 운영 작업/rollback 관리 탭, web 일괄 등록, 시즌 초기화가 포함되지 않습니다.

## 실시간 편집

여러 사용자가 동시에 다루는 일부 화면에는 실시간 편집 상태가 표시됩니다.

- 일반 내전 엔트리 편성: 활성 길드 멤버의 실시간 갱신, 편집은 화면 권한 보유자만 가능
- 진행 중 일반 시리즈의 픽밴
- 경매 모집의 참가자 roster
- `BIDDING` 상태 경매의 입찰 작업대

**연결됨**은 변경 알림을 받을 수 있는 상태이고, **저장 중**은 HTTP mutation을 처리하는 상태이며, **충돌**은
다른 운영자의 변경 때문에 최신 데이터를 다시 확인해야 하는 상태입니다. 브래킷, 라인업, match 결과, 결과
조회 화면은 WebSocket을 열지 않고 HTTP 응답으로 최신 상태를 확인합니다.

## 빠른 도구

화면 오른쪽 아래의 빠른 도구에서는 미니게임, 빠른 Riot 전적 검색, 타이머를 열 수 있습니다. 이 도구들은
진행 중인 내전이나 경매 데이터를 직접 변경하지 않습니다.
